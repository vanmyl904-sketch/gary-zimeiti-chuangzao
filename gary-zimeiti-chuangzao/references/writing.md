# 数字人口播创作

## 观点复筛

从选定视频列出原话、时间点和各自对应的获客问题。把直接讨论某观点的评论单列，比较有多少独立观众追问、举例或反驳，核对同题不同作者的互动。同作者的相关作品可补论证，不能增加独立样本数量。相邻行业、备婚用户内容和高互动清单可以补需求或包装证据，注明与本题的距离。资料不足时说清这是待验证选题。

写稿前简要交付：选哪个观点、原文为什么这样讲、哪几位同行提出了不同证据、评论在讨论哪一部分。保持原观点的核心矛盾、适用范围、关键事实和因果。新增情境会改变原题时先与用户确认。同类文案借用结构或短语要说清出处，表达和取材做自己的编辑。

## 九项检查

1. 观点是否明确且有原文和同题旁证。
2. 标题是否明确给哪类商家看、有具体获客问题。
3. 话题标签是否符合行业和视频实际内容。
4. 开头是否让目标老板在第一时间听见熟悉的困境。
5. 正文有没有给商家一个可以照着做的获客动作，片尾能否自然接住愿意咨询课程的老板。
6. 结构是否围绕一个问题，顺序能否用旁白听懂。
7. 其他博主的案例、分歧与适用条件是否有明确来源。
8. 评论热点是否直接与观点相关，有没有虚报热度或从一句评论推断客资结果。
9. 每句有没有可制作的主画面，画面是否展示得出这个判断。

正文面向商家。稿中教商家制作的示例应让目标新人或合作客户看懂。可以用获授权的既有素材、原创插画、流程动画或标明是示意的界面。旁白稿不依赖用户前往门店取景。示意画面不能证明真实订单、客户故事或预约结果。

## 收尾

先说商家想获得的具体咨询，然后说这个行业拍内容最真实的困难，最后自然邀请「可以来找我聊聊呀」。例如婚庆公司可以聊同城备婚咨询、平时忙现场、不会选题和镜头前放不开。酒店宴会部可落到问档期、约看厅和不知如何在扫厅之外找内容。婚礼堂可落到如何说明各个厅适合什么样的婚礼。课程详情在抖音站内咨询时承接。

## 字数验收

每篇口播正文必须正好 **380 字**，包括观众会听到的开头、正文和固定收尾。汉字、英文字母和数字各计一字。标点、空格、换行和 Markdown 标记不计。标题、封面、话题、分镜及证据说明单独放置，不参与计数。

将录制正文单独传入计数命令，改完任何一句后重新核验。补字优先补同题证据或有用信息，删字优先删赘句，保留已经确认的行业收尾。提交时标注「口播正文 380 字」。

```bash
python3 -c 'import sys; print(sum(c.isalnum() for c in sys.stdin.read()))' < spoken-copy.txt
```

## 交付

交付标题、封面、话题标签、完整可读的口播稿、对应画面及来源链接。若比较借鉴程度，分别核对原句、观点和结构。发出后看留存、收藏及分享，单独记目标商家的有效课程咨询。若门店采用示例，在门店侧另记同城咨询、预约等动作。
